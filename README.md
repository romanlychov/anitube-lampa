# AniTube для Lampa

Експериментальний плагін для поступової інтеграції каталогу AniTube у Lampa.

## Встановлення

У Lampa відкрийте **Налаштування → Розширення → Додати плагін** і вставте адресу:

```
https://romanlychov.github.io/anitube-lampa/anitube-lampa.js
```

Після додавання перезапустіть Lampa. У меню має з'явитися пункт **AniTube**.

## Версії

### 0.2.10 — поточна

- Замінено піктограму AniTube у боковому меню на власний знак у стилі контурних піктограм Lampa: шестикутна рамка, кнопка відтворення та невеликий акцент.
- Виправлено адресу каталогу: замість загальної головної сторінки використовується розділ аніме AniTube `/f/sort=date/order=desc/page/1/`.
- Парсер каталогу обмежено точним контейнером `#dle-content article.story` і заголовком `h2[itemprop="name"]`. Це має прибрати сторонні картки з інших блоків сайту.
- Пошук переведено на маршрут `/anime/` з POST-запитом та параметрами AniTube `do=search`, `subaction=search`, `story`, відповідно до відкритої бібліотеки anitube-ua-lib.
- Додано базові українські відповідники назв «Ван Піс», «Наруто», «Атака титанів» і «Клинок, що знищує демонів».
- Для запиту плейлиста додано заголовки контексту сторінки та AJAX-запиту, щоб спробувати усунути відповідь 403.

**Важливо:** усі зміни опубліковані для перевірки на телевізорі. Не підтверджено, чи AniTube дозволить запити плейлиста з Lampa: сервер може відхиляти зовнішні запити або вимагати інші параметри/сесію. Сезони та озвучення залежать від фактичної структури відповіді плейлиста.

### 0.2.9 — поточна

- Переписано парсер каталогу: тепер він бере тайтли лише з `#dle-content article.story`, а не з усіх `.html`-посилань сторінки. Це має прибрати сторонні результати на кшталт «Аніме субкультура» та «Наші друзі».
- Постер тепер шукається лише всередині відповідної картки `article.story` через `span.story_post img`, без підйому до спільних батьківських блоків. Це експериментальне виправлення повторюваних/чужих постерів.
- Реалізовано запит списку серій через `engine/ajax/playlists.php?news_id=...&xfield=playlist`, який використовується бібліотекою `anitube-ua-lib` для отримання плейлиста AniTube.
- Додано розбір груп/пунктів озвучення з відповіді AJAX та резервний розбір `RalodePlayer.init(...)`, якщо AJAX-плейлист не повернув даних.
- Для прямих `.m3u8` і `.mp4` посилань додано передачу до штатного програвача Lampa; посилання FenixPlay `/vod/` продовжують оброблятися окремою гілкою.

**Важливо:** отримання плейлиста тепер реалізоване, але фактичний формат відповіді на всіх тайтлах і запуск FenixPlay ще треба перевірити на телевізорі. Сам факт знаходження серій не гарантує, що їхній відеопотік уже сумісний із програвачем Lampa.

### 0.2.8 — попередня

Перероблено екрани каталогу та деталей:
- Додано `scroll.minus()` на екранах каталогу та деталей, щоб штатний Scroll Lampa отримував висоту робочої області; це експериментальне виправлення, потрібна перевірка на телевізорі.
- Виправлено оновлення списку фокусованих елементів після асинхронного завантаження каталогу.
- Додано реєстрацію відеоджерела AniTube через `Lampa.Manifest.plugins`, щоб відкривати пошук AniTube з контекстного меню картки.
- Прибрано кнопку відкриття сторінки через вбудований браузер Lampa, якого немає у збірці користувача.
- Додано спробу розібрати посилання FenixPlay, отримати дані серії через playback API, показати вибір озвучення та передати HLS-посилання штатному `Lampa.Player.play()`.
- Уточнено повідомлення про відсутність `/vod/`: воно більше не стверджує, що посилань немає на сайті взагалі, лише що їх не знайдено у завантаженому HTML.

**Важливо:** інтеграція FenixPlay поки експериментальна. У HAR підтверджено, що API серії вимагає тимчасовий заголовок `X-Fenix-Playback`, а медіаплейлисти використовують окремий короткоживучий токен доступу. Автоматичне отримання всіх потрібних токенів і сумісність окремих HLS-аудіо/відеопотоків зі штатним програвачем ще не підтверджені. Потрібен тест на телевізорі.

## Перевірка

Версія 0.2.10 опублікована для тестування. Каталог, фільтрація карток, постери та отримання списку серій через AJAX поки не підтверджені на реальному телевізорі. Отримання токенів FenixPlay і сумісність потоків також залишаються експериментальними. HTTP 200 означає лише, що Lampa отримала JavaScript-файл; це не підтверджує роботу каталогу, токенів або відтворення.
